# SPEC 1.8 — Interactions (native motion authoring)

Status: SPECCED (source-verified, Elementor 4.2.1 free). Surprising baseline:
the kit ALREADY ships `interaction()`/`interact()` (kit.mjs:660-693) emitting the
correct envelope, and the ultra-mcp plugin passes the `interactions` key through
verbatim into Document::save (verified: zero stripping anywhere in the chain).
1.8 = surface it in JSX, harden against the platform's real constraints, verify.

## What it unlocks

`motion={{...}}` on any atomic element → native entrance/scroll animations,
editable in the editor's Interactions tab (V4 panel, verified present), no custom
JS, delivered by Elementor's own Motion-lib runtime.

## Native contract (verified, with the sharp edges)

1. Wire shape per element: `interactions: {version: 1, items: [interaction-item]}`.
   Item envelope: `{$$type:'interaction-item', value:{interaction_id(string),
   trigger(string), animation(animation-preset-props), breakpoints?}}`.
   Animation: `{effect: fade|slide|scale|custom, type: in|out,
   direction: ''|left|right|top|bottom|top-left|…,
   timing_config: {duration,delay as size-ms envelopes}, config, custom_effect?}`.
2. **Save semantics: invalid items are silently STRIPPED, not rejected** —
   the only hard failure is >5 items per element (whole save throws). Compiler
   must therefore validate at build time; the server won't tell you.
3. `interaction_id` auto-assigned as `{postId}-{elementId}-xxxxxxx` when missing.
4. **Free-tier reality** (spec MUST encode this):
   - Frontend honors only `load|scrollIn|scrollOut`; hover/click/scrollOn items
     save fine but no-op without Pro's handler.
   - `easing`, `replay`, `repeat/times/start/end/relativeTo` are DEAD on free —
     handler hardcodes defaultEasing and replay:false.
   - LATENT FREE BUG: `scrollOut` references an out-of-scope var and throws at
     trigger time in 4.2.1 free — do not default to scrollOut; gates use scrollIn.
   - `custom` effect (keyframes) is Pro-only at runtime.
5. Feature flags: `e_interactions` (default ACTIVE) + `e_atomic_elements`
   (default active on fresh 4.x) — ON for all our target stacks; if off, the key
   is preserved raw but never rendered. Capability probe belongs in eu-studio
   doctor, not the compiler.
6. Delivery: one footer JSON script + `data-interaction-id` per element
   (= origin_id ?? element id); Motion lib enqueued only when items exist.
   Template-part deploys bypass Document::save (raw meta write) — items must be
   emitted pre-valid; frontend cache rebuilds lazily so this works, keep it.
7. **prefers-reduced-motion: NOT respected natively** (verified zero handling).

## Authoring surface

```jsx
<section motion={{ effect: 'fade', trigger: 'scrollIn' }}>
<card motion={[{ effect: 'slide', direction: 'top', duration: 500, delay: 120 }]}>
```
- `motion` accepts one object or array (≤5, build-error above).
- Defaults: trigger `scrollIn` (NOT scrollOut — see free bug), type `in`,
  duration 600ms, delay 0. `effect:'custom'`, hover/click triggers, easing/replay
  allowed but tagged `pro:` in types + API card ("saves everywhere, animates with
  Pro"); lint warns when emitted for a free-target project.
- `excludeOn: ['mobile']` → breakpoints envelope.
- Sugar maps to existing `interact(node, [interaction(...)])` — the JSX layer is
  a thin adapter, kit stays canonical.

## Changes

- kit.mjs: fix `config.$$type` 'animation-config' → 'config-v2' (harmless today,
  canonical tomorrow); add breakpoints support to `interaction()`.
- runtime/x/prelude: `motion` prop on all intrinsic atomic tags → interact().
- lint.mjs: envelope validation mirroring validation.php (item shape, enums,
  size envelopes, ≤5, custom-effect keyframe rules) — because the server strips
  silently, lint is the ONLY honest failure surface.
- types.d.ts: MotionSpec with pro-flagged fields documented.
- decompile.mjs: interactions → `motion` prop round-trip (read items, invert).
- **Reduced-motion (a11y, our value-add over native)**: compiler optionally
  emits a site-level CSS guard via the standard classes pipeline:
  `@media (prefers-reduced-motion: reduce){ [data-interaction-id]{ … } }` is NOT
  expressible (JS-driven), so instead: emit a tiny opt-in snippet in the runtime
  carrier that removes interaction data nodes when reduced-motion is preferred.
  Config: `site.config.mjs → motion: {respectReducedMotion: true (default)}`.
  Document that native Elementor does not do this.
- Verification gates (eu-studio): screenshots must be motion-deterministic —
  gate runs with interactions disabled (strip footer JSON via page-eval before
  capture) OR wait-for-settle: spec mandates strip-before-capture as primary
  (deterministic) + one optional "motion smoke" pass with scrollIn forced.

## Test contract

Unit: envelope exactness vs validation.php rules (fixtures for every enum),
≤5 enforcement, pro-field lint warnings, decompile round-trip, config-v2 key.
Integration (:8947): deploy page with load+scrollIn items → read back saved doc
(items intact, ids assigned) → footer JSON present → Motion lib enqueued →
screenshot after strip shows final-state layout → interact() on a template part
(raw-meta path) still renders footer JSON. Negative: 6 items → build error;
invalid enum → lint error (and confirm server would have stripped silently).
